Discord Bot Documentation
=========================

Project
-------
Name: discord-multibot
Runtime: Node.js
Main file: index.js
Discord library: discord.js v14
Database: sql.js SQLite database saved to bot.db
API server: Express, default port 3001

This project is a multi-feature Discord slash-command bot with Roblox,
utility, social, music, finance, games, admin, and fun commands. It also
starts a small Express API server for health, stats, and media scraping.


Important Security Note
-----------------------
Do not publish real tokens, API keys, or bot credentials.

Keep .env.example limited to placeholders. If a live key is ever shared,
committed, or uploaded, rotate it in the provider dashboard immediately.

Never paste DISCORD_TOKEN, GEMINI_API_KEY, HF_API_TOKEN, weather keys, Genius
keys, or Cat API keys into public documentation.


Quick Start
-----------
1. Open a terminal in:

   C:\Users\santi\Desktop\discord-bot

2. Install dependencies:

   npm install

   The project also includes pnpm files, so pnpm can be used if preferred:

   pnpm install

3. Create a .env file from .env.example:

   copy .env.example .env

4. Edit .env and set real credentials.

5. Deploy slash commands:

   npm run deploy-commands

6. Start the bot:

   npm start

7. For development with auto-restart:

   npm run dev


NPM Scripts
-----------
npm start
  Runs node index.js.

npm run dev
  Runs node --watch index.js.

npm run deploy-commands
  Loads every command under src/bot/commands and registers slash commands with
  Discord. If DISCORD_GUILD_ID is set, commands deploy to that guild instantly.
  Commands are also deployed globally, which can take up to about 1 hour.

npm test
  Runs all three offline smoke tests (no Discord connection or API keys needed):
  image effects, the prefix parser, and the media resolver.

npm run test:effects
  Runs every registered image effect against a generated still image and a
  generated animated GIF, printing the output size, format, and timing.
  Pass effect names to check only those, and --write <dir> to save the results:

    node scripts/smoke-effects.js --write /tmp/out magik globe meme

npm run test:prefix
  Checks prefix alias resolution, greedy text options, and attachment handling.

npm run test:media
  Checks the media resolution order (attachment, link, avatar, reply, history).

  Comma-separated Discord user IDs that count as bot owners.

  Optional guild/server ID for instant test command deployment.

  Express API port. Defaults to 3001.

  Shared secret for the /web/* playground routes used by

  xocat.online Pages project. Leave empty to keep those routes disabled.

  Cloudflare Tunnel connector token. When set, the bot runs cloudflared itself

  Override the cloudflared binary. Defaults to bin/cloudflared.exe on Windows,
  bin/cloudflared-linux-amd64 on Linux, or whatever is on PATH.

PREMIUM_USER_IDS
  Optional comma-separated premium user IDs.

GEMINI_API_KEY
  Used by AI/Gemini-related features if present.

HF_API_TOKEN
  Used by Hugging Face-related features if present.

OPENWEATHER_API_KEY
  Used by /weather.

GENIUS_API_KEY
  Used by lyrics commands.

EXCHANGE_API_KEY
  Used by exchange-rate commands.

CAT_API_KEY
  Optional key for cat image commands.


Project Structure
-----------------
index.js
  Main entry point. Loads .env, initializes the database, creates the Discord
  client, starts the Express API server, logs in to Discord, and checks timer
  reminders every 10 seconds.

deploy-commands.js
  Recursively loads slash commands from src/bot/commands and deploys them to
  Discord through the REST API.

src/bot/client.js
  Creates the Discord.js client with intents, partials, command loading, and
  event loading.

src/bot/events/ready.js
  Logs startup information and rotates bot presence every 30 seconds.

src/bot/events/interactionCreate.js
  Handles slash commands, command usage tracking, command errors, button
  interactions, and autocomplete.

src/bot/commands/
  Slash command files grouped by category. Files whose name starts with an
  underscore and ends in .cjs are shared helpers, not commands, and the loader
  skips them.

src/bot/commands/images/
  The image-editing commands: /image (the effect engine) plus /meme,
  /motivate, /speechbubble, and /watermark.

src/services/imageEffects.js
  The image effect registry and all effect implementations. See "Image Effects".

src/services/mediaResolver.js
  Works out which image a command should operate on, and downloads it safely.
  See "Finding Images".

src/services/mediaCommand.js
  Shared runner for effect commands: resolve, apply, retry smaller if the result
  is too big to upload, reply.

src/services/tagService.js
  Storage and permission rules for the per-server /tag system.

src/services/prefixCommandService.js
  Bridges dot-prefix messages onto the slash command schemas. See
  "Prefix Commands".

src/utils/frames.js
  Frame decode/encode, displacement remapping, and text rendering primitives
  used by the effect engine.

scripts/
  Offline smoke tests. See the npm scripts section.

src/api/server.js
  Express API server with /health, /stats, /scrape, and /api/scrape routes.

src/api/webRoutes.js
  Authenticated /web/* routes for the xocat.online playground.

src/services/tunnelService.js
  Supervises a cloudflared child process when TUNNEL_TOKEN is set.

src/database/db.js
  sql.js database setup and helper functions.

src/database/schema.sql
  Database table definitions.

src/services/
  API/service wrappers for external data sources.

src/utils/
  Shared helpers for embeds, constants, pagination, and premium checks.

src/data/
  Local JSON data used by game/Roblox-related commands.

bin/yt-dlp.exe
  Local yt-dlp binary used by scraping/media extraction features.

bot.db
  Local SQLite database file. This stores runtime data.

- Guilds
- GuildMessages
- GuildMembers
- GuildPresences
- MessageContent
- DirectMessages

Enabled partials:
- Channel
- Message

Commands are loaded recursively from:

src/bot/commands

Each command file should export either one command object or an ARRAY of them
(src/bot/commands/images/effects.js exports an array, one entry per promoted
image effect). A command object has:
- data: SlashCommandBuilder or compatible command data
- execute(interaction): async function that runs the command

Optional:
- autocomplete(interaction): async function for autocomplete options
- guildOnly: true to refuse the command outside a server
- skipUsageTracking: true to keep the command out of command_logs
- prefixAliases: extra dot-prefix names for the command, e.g. ['pfp', 'icon'].
  An entry may also be { alias, prepend } to supply leading arguments, which is
  how `.haah` reaches `/mirror direction:haah`
- prefixGreedy: the name of a string option that should soak up the rest of a
  dot-prefix line, so multi-word input does not need quotes

Image Effects
-------------
The bot ships a port of esmBot's image-editing command set. esmBot implements
its effects as native libvips pipelines; sharp is libvips too, so the colour,
geometry, and compositing effects translate almost directly. Two things sharp
does not expose are implemented in JavaScript instead:

- mapim (displacement remapping), in src/utils/frames.js, which powers circle,
  swirl, explode, implode, wall, and globe
- ImageMagick's liquid rescale, implemented as seam carving in
  src/services/imageEffects.js, which powers magik

Every effect operates on decoded RGBA frames, so all of them work on still
images and animations alike. A still input becomes a 15 or 30 frame animation
for the effects that are inherently animated (spin, squish, globe, bounce,
fade, slide).

How to run one
--------------
Discord caps an application at 100 global chat-input commands, and the rest of
the bot uses 77 of them, so the 49 effects cannot all have their own. They are
reachable four ways:

1. Its own slash command, for the 25 most-used effects:

     /deepfry
     /magik
     /hue amount:90 user:@someone
     /meme text:top text, bottom text

   Which effects these are is the PROMOTED list in
   src/bot/commands/images/effects.js. Moving a name in or out of that list adds
   or removes its command; deploy-commands.js refuses to deploy past Discord's
   cap, so an over-long list fails loudly rather than wiping every command.

2. A grouped command, where several effects differ only by one setting:

     /mirror direction:haah        (haah, waaw, woow, hooh)
     /gifspeed mode:speed amount:2 (speed, slow, reverse, freeze, unfreeze)
     /caption style:whisper        (caption, caption2, whisper, snapchat)

3. /image, which reaches every effect and has autocomplete over all 49:

     /image effect:tile
     /image effect:vignette

4. As a dot-prefix command, which is how esmBot exposes them. Every effect name
   and every alias works, whether or not the effect has a slash command, and
   prefix commands do not count against Discord's limit:

     .deepfry
     .magik
     .haah
     .speed 2
     .meme top text, bottom text

Run /image effect:list or /help category:effects to see the full list in
Discord.

Colour and filters:
  blur, sharpen (unblur), grayscale (gray, greyscale, grey, bw),
  invert (inverse, negate, negative), sepia, hue (hueshift, recolor),
  deepfry (fry, nuke, df), jpeg (jpg, morejpeg, needsmorejpeg, jpegify),
  pixelate (pixel, small), vignette, flag

Geometry:
  flip (upsidedown), flop, haah (mirror2), waaw (mirror), woow (mirror3),
  hooh (mirror4), rotate, crop, wide (w19), stretch (aspect, ratio),
  squish, tile, wall

Distortion:
  circle (cblur, radial, radialblur), swirl (whirl), explode (exp),
  implode (imp), globe (sphere), spin, magik (magic, cas, contentawarescale)

Text:
  meme, motivate (poster, demotivational), caption, caption2 (ifunny),
  whisper, snapchat (snap), speechbubble (speech, bubble), watermark (wm),
  uncaption (uncap)

Animation:
  reverse (backwards), speed (fast, faster), slow (slower), freeze (noloop,
  once), unfreeze, bounce (bouncy), fade (fadein), slide (shift), gif (gifify)

Shared options
  text      Text for the effects that need it. meme and motivate split the top
            and bottom halves on a comma; escape a literal comma with \,
  amount    Effect strength. What it controls depends on the effect: degrees for
            hue and rotate, quality for jpeg, a multiplier for speed and slow,
            opacity for watermark, bubble size for speechbubble, and so on.
  font      futura, helvetica, impact, roboto, ubuntu, arial, times,
            futura-pt, serif, sans, mono.

            futura is Futura Extra Black Condensed (assets/fonts/caption.otf),
            the same face esmBot captions with, and it is /caption's default.
            helvetica is Helvetica Neue (caption2.ttf), which is what esmBot
            uses for its caption2/iFunny bar and for snapchat. impact is Anton,
            the closest free substitute, since Impact cannot be redistributed.
            arial, times, serif, sans, and mono resolve through the host's
            fontconfig. futura-pt is the font /caption used before esmBot's face
            was vendored, kept so the old look is still reachable.

            Fonts can be deleted from assets/fonts: the engine checks for each
            file at startup and follows a fallback chain, so a missing font
            substitutes rather than breaking the command. See
            assets/fonts/README.txt for provenance and licence notes — two of
            the bundled faces are commercial typefaces taken from esmBot.

            When adding a font, the family recorded in FONT_DEFINITIONS
            (src/utils/frames.js) must contain no Pango style keywords (Bold,
            Black, Condensed, Light, Italic). Pango strips those out of the
            family and reinterprets them as weight/stretch requests, which
            misses the real face and renders a synthesised fake-bold instead.

            Emoji in caption text are drawn as Apple artwork rather than left
            to the host's emoji font, which would otherwise give Segoe on a
            Windows box, a monochrome outline on a bare Linux one, and a blank
            box on a machine with no emoji font at all. src/utils/emojiText.js
            replaces each emoji with a one-em marker square before the string
            reaches Pango, then composites the artwork into wherever that
            square landed, so Pango still does the wrapping and alignment.
            Artwork is fetched once per emoji and cached for the process's
            life; one that cannot be fetched leaves a gap rather than failing
            the command. A lone character that defaults to text presentation
            (© ™ ‼) stays as text — only a picker's variation selector, a skin
            tone, a keycap, or a ZWJ join makes it artwork.
  format    Force gif, png, or webp output.

Limits
  Inputs are capped at 25 MB and downscaled to 512 px on the longest side
  (320 px for globe and magik, which are the expensive ones). Animations are
  capped at 60 frames. If the result is still too large to upload, the effect is
  retried at 384, then 256, then 192 px with fewer frames; the reply footer says
  when that happened.

Effects reachable only through /image and the prefix
  sharpen, sepia, vignette, flag, rotate, crop, tile, wall, circle, fade,
  slide, and gif (gif duplicates /togif). These are the ones that lost the
  coin toss for the last few command slots — they work exactly the same, they
  just need /image or a prefix call. Promote any of them by adding the name to
  PROMOTED in src/bot/commands/images/effects.js and demoting another.

Effects that were deliberately not ported
  esmBot builds gamexplain, scott, soos, spotify, reddit, homebrew, sonic,
  uncanny, and its branded watermarks (iFunny, 9GAG, HyperCam, and friends) out
  of bundled third-party artwork. Those images are copyrighted and do not belong
  in this repository, so those effects are absent. Where an overlay can be drawn
  instead of shipped it was kept: speechbubble draws its bubble as SVG, vignette
  generates its own gradient, flag draws pride flags from stripe definitions,
  and /watermark takes arbitrary text rather than a fixed logo.

Adding an effect
  Add an entry to the EFFECTS object in src/services/imageEffects.js. It is
  immediately reachable via /image and as a prefix command; add its name to
  PROMOTED in src/bot/commands/images/effects.js to give it a slash command too.

    myeffect: {
      description: 'What it does',
      aliases: ['alias1'],
      category: 'colour',
      params: { amount: { min: 0, max: 10, default: 1 } },
      run: (image, params) => mapFrames(image, frame => frame.blur(2)),
    }

  `image` is { frames, width, height, delays, loop, animated }; `run` returns the
  same shape. Set alwaysGif: true if a still input should produce an animation,
  and maxSize to cap the working resolution. The effect immediately becomes
  available to /image, to /help, and as a dot-prefix command; add it to
  scripts/smoke-effects.js PARAMS if it needs sample input.


Finding Images
--------------
Media commands do not require an attachment. src/services/mediaResolver.js
looks for an image in this order and takes the first hit:

1. the command's file (or image) attachment option
2. the link option: an image URL, a custom emoji, or a user ID
3. the user option, which resolves to that user's avatar
4. attachments, embeds, or stickers on the invoking message
5. a custom emoji, unicode emoji, or bare image URL in the message text
6. the same checks against the message being replied to
7. the same checks against the last 50 messages in the channel

So all of these do the same thing:

  /image effect:deepfry file:<upload>
  .deepfry                         (with an image attached)
  .deepfry                         (replying to a message with an image)
  .deepfry https://example.com/cat.png
  .deepfry <:blobcat:123456789012345678>
  .deepfry @someone
  .deepfry                         (uses the last image posted in the channel)

Unicode emoji resolve to Apple artwork (the iOS/macOS emoji set, mirrored from
iamcal/emoji-data at 160px). Lottie stickers are skipped, since they are vector
animations that sharp cannot read.

Downloads go through src/utils/network.js, which resolves the hostname and
refuses private, loopback, and link-local addresses at every redirect hop, so a
user-supplied URL cannot be used to reach anything on the host's network. The
size ceiling is enforced while streaming, so an oversized file never lands in
memory in full.

Commands using the resolver: /image, /meme, /motivate, /speechbubble,
/watermark, /caption, /uncaption, /togif, /compress, /imgtotext, /qr decode,
and /raw.


Prefix Commands
---------------
src/services/prefixCommandService.js runs slash commands from ordinary messages
starting with "." It reads each command's own SlashCommandBuilder schema, so a
command never needs prefix-specific code.

Arguments can be positional or named:

  .dice sides:20 count:3
  .dice 20 3
  .image hue amount:90

Multi-word values normally need quotes, unless the command declares a
prefixGreedy option, in which case that option soaks up the rest of the line:

  .meme top text, bottom text
  .timer 10m take out the bins
  .tag add welcome hello and welcome to the server
  .8ball will it rain tomorrow

Attachment options are filled from the message itself, or from the message being
replied to; they never consume a typed argument.

Aliases come from two places:
  - each command's prefixAliases export, for example .pfp -> /avatar, or
    .haah -> /mirror direction:haah when the entry carries a prepend
  - every image effect name and alias that is not already a command, routed to
    /image with the effect pre-filled, for example .tile -> /image effect:tile

A real command name always wins over an alias, so .caption keeps running
/caption. The table is built once per process and cached on the client.

A bare number is understood where it makes sense: `.hue 90` and `.wide 4` put
the number in the effect's `amount`, because an effect's own parameters are
declared before the image-source options.


Database
--------
The database uses sql.js, a pure JavaScript SQLite implementation.

Database file:

bot.db

Schema file:

src/database/schema.sql

Tables:

premium_users
  Stores premium access by user ID, tier, activation time, and optional expiry.

user_profiles
  Stores XP, level, command count, and daily timestamps.

crypto_tracks
  Stores tracked crypto transactions.

timers
  Stores timer/reminder data. index.js checks due reminders every 10 seconds.

command_logs
  Stores command usage analytics.

game_states
  Stores serialized persistent game state.

tags
  Per-server /tag snippets: name, content, owner, use count, and timestamps.
  Names are stored lower-cased, so lookups are case-insensitive.

Database helpers in src/database/db.js:
- initDatabase()
- getDatabase()
- saveDatabase()
- dbAll(sql, params)
- dbGet(sql, params)
- dbRun(sql, params)
- getOrCreateProfile(userId)
- incrementCommandUsage(userId, commandName, guildId)

The database auto-saves every 30 seconds and also saves on dbRun().


API Server
----------
The API server is created in src/api/server.js and started from index.js.

Default port:

3001

Change with:

API_PORT=your_port

Routes:

GET /health
  Returns bot/API status, uptime, bot tag, guild count, command count, and a
  timestamp.

GET /stats
  Returns guild count, estimated user count, command count, total commands run,
  total tracked users, premium user count, and uptime.

POST /scrape
  Body: { "url": "https://example.com/video" }
  Uses bin/yt-dlp.exe to extract media metadata and a direct media link.

GET /api/scrape?url=...
  Backward-compatible scraper endpoint.

Rate limit:
  60 requests per minute per client.


Web playground routes (/web/*)
------------------------------
These back https://xocat.online/bot/playground and live in
src/api/webRoutes.js. They are not for browsers: a Cloudflare Pages Function on
xocat.online checks the visitor's Discord sign-in and then calls these with a
shared secret, so the bot's address and the secret both stay server-side.

Every /web route requires:

  Authorization: Bearer <WEB_API_SECRET>

If WEB_API_SECRET is empty the whole router answers 503, so an unconfigured
deployment is closed rather than open.

GET /web/effects
  The effect registry as JSON: name, description, category, aliases, whether it
  always outputs a GIF, its text/amount/font parameters, and its boolean flags.
  Also returns the font list, the flag names, and the size limits. The website
  builds its form from this, so promoting or renaming an effect needs no
  website deploy.

GET /web/guilds
  The bot's guild IDs. The website intersects them with the visitor's own guild
  list to enforce "you must share a server with the bot".

POST /web/effect?effect=<name>[&text=&amount=&font=&format=&alpha=&vertical=
                              &reverse=&bottom=&flip=&caseSensitive=&url=]
  Body: raw source image bytes, or omit the body and pass ?url= to have the bot
  download it (through the SSRF guard in src/utils/network.js).
  Returns the finished image, with details in X-Effect-Name, X-Effect-Format,
  X-Effect-Width, X-Effect-Height, X-Effect-Frames and X-Effect-Notes.
  Limits: 8 MB in, 6 MB out, 20 renders per minute. Oversized results are
  retried at smaller sizes exactly as the Discord commands do.

GET /web/media?url=...
  The same yt-dlp probe POST /scrape uses (src/services/mediaProbe.js).


Command Flow
------------
1. Discord sends an interaction.
2. src/bot/events/interactionCreate.js receives it.
3. The command is found in client.commands by interaction.commandName.
4. Command usage is logged with incrementCommandUsage().
5. The command execute() function runs.
6. Errors are caught and sent back as an error embed.


Premium / Owner Access
----------------------
Premium helpers live in:

src/utils/premium.js

Owner IDs come from OWNER_IDS.
Premium IDs can come from PREMIUM_USER_IDS or the premium_users database table.
Owners always count as premium.

Current interactionCreate.js comment says premium requirement checks were
removed, so commands may not currently enforce premium access globally.
Individual commands may still check ownership or premium manually.


Adding a New Command
--------------------
1. Create a new .js file inside an existing category under:

   src/bot/commands

2. Export command data and execute().

Example structure:

const { SlashCommandBuilder } = require('discord.js');

module.exports = {
  data: new SlashCommandBuilder()
    .setName('example')
    .setDescription('Example command'),

  async execute(interaction) {
    await interaction.reply('Hello!');
  },
};

3. Deploy slash commands:

   npm run deploy-commands

4. Restart the bot:

   npm start


Adding a New Service
--------------------
1. Add a file under src/services, for example:

   src/services/exampleService.js

2. Keep API-specific code in that service file.
3. Import the service from the command that needs it.
4. Store API keys in .env, never directly in source.

Common Issues
-------------
Bot does not start:
- Check DISCORD_TOKEN.
- Check Node.js is installed.
- Run npm install.

Slash commands do not appear:
- Run npm run deploy-commands.
- If global commands were used, wait for propagation.
- Set DISCORD_GUILD_ID for instant testing in one server.

Database changes are not saved:
- Make sure the process has permission to write bot.db.
- Check console for [DB] Save error messages.

Scrape command/API fails:
- Confirm bin/yt-dlp.exe exists.
- Check whether the target site blocks scraping.
- Check API rate limits and URL validity.

Image/OCR features fail:
- Confirm eng.traineddata exists.
- Confirm sharp/tesseract dependencies are installed correctly.
- sharp must be 0.34 or newer. The effect engine builds animations with
  sharp's join option, which older releases do not have.
- Run npm run test:effects to check the whole effect registry offline.

An image command says it cannot find an image:
- The resolver only scans the last 50 messages, and only if the bot can read
  message history in that channel.
- Attach the file, reply to the message that has it, or pass link:<url>.

Weather/lyrics commands fail:
- Check the related API key in .env.


Deployment Notes
----------------
This bot is a long-running Node.js process. Host it somewhere that supports
always-on Node processes, such as:
- VPS
- Windows server
- Linux server
- Railway/Fly/Render-style service, if compatible with local SQLite and files

Important deployment files:
- .env
- bot.db
- bin/yt-dlp.exe, if scraper features are needed
- eng.traineddata, if OCR features are needed

For production, consider:
- Keeping bot.db backed up.
- Not committing .env or bot.db to public repos.
- Rotating leaked keys.
- Running the process with a manager such as pm2 or a system service.


Maintenance Notes
-----------------
After changing command names, descriptions, or options:

npm run deploy-commands

After changing only command execution logic:

Restart the bot.

After changing schema.sql:
- Back up bot.db first.
- Restart the bot so initDatabase() runs schema updates.

After changing API routes:
- Restart the bot/API process.
